# 飞书内容总表与平台子表写回规范

## 1. 数据职责

推荐结构：

| 表 | 职责 |
|---|---|
| 内容总表 | 保存母稿、母稿标题、主题、内容 ID 和对标内容 |
| 小红书子表 | 保存小红书标题、正文、标签、完整分页文案、图片和发布状态 |
| 抖音/视频号子表 | 保存各平台脚本、封面、媒体和发布状态 |

内容 ID 或关联记录用于跨表关联。总表不是直接发布表；平台图片默认写入对应平台子表。

## 2. 权威来源

平台子表存在“关联母稿”时：

1. 读取关联的总表记录。
2. 以“母稿标题”和“母稿正文”为源稿。
3. 将“小红书正文”“图片分页文案”和历史附件视为派生内容。

除非用户明确要求使用平台编辑稿，否则不能用已摘要的分页文案生成“完整版”图片。

## 3. 工具优先级

1. 首选 `lark-cli`。
2. Base 有可用 CLI 时，不使用浏览器填写表格或上传附件。
3. 只有 CLI 不可用且用户明确同意时，才考虑界面操作。

预检命令：

```bash
lark-cli whoami
lark-cli base +field-list --base-token <base> --table-id <table>
lark-cli base +record-get --base-token <base> --table-id <table> --record-id <record>
```

字段名和字段类型必须从 `+field-list` 获取，不能根据记忆猜测。

## 4. 目标记录定位

优先使用用户给出的记录 ID。没有记录 ID 时，按平台内容 ID 或唯一业务键查找：

- 匹配 1 条：继续。
- 匹配 0 条：用户已经确认母稿并要求执行完整流程时，视为已授权创建对应平台子记录；其他任务只有用户明确授权时才创建。
- 匹配多条：停止并报告重复。

在任何写入前记录：Base token、table ID、record ID、内容 ID 和关联母稿 record ID。

母稿记录存在但平台子记录不存在时：

1. 读取平台子表中现有业务编号，计算下一条未占用的平台内容 ID。
2. 创建唯一平台子记录，并关联到当前母稿。
3. 读回平台内容 ID、record ID 和关联母稿，确认唯一后继续。

不得猜测编号、复用旧 ID，或因重试创建重复记录。

## 5. 字段语义

常见字段：

| 语义 | 常见字段名 |
|---|---|
| 平台内容 ID | 小红书内容ID、视频号内容ID、抖音内容ID |
| 关联母稿 | 关联母稿、内容总表记录 |
| 平台标题 | 小红书标题、发布标题 |
| 封面标题 | 封面标题 |
| 封面副标题 | 封面副标题 |
| 平台短正文 | 小红书正文、发布正文 |
| 逐页完整文案 | 图片分页文案、图文分页文案 |
| 图片附件 | 图片 01｜封面、图片 02…… |
| 内容状态 | 内容状态、处理状态 |
| 发布状态 | 是否发布 |

## 6. “图片分页文案”的硬性格式

该字段保存每页实际渲染的完整文字，而不是概述。

正确结构：

```text
第1页｜页面任务
主标题：……
副标题：……

该页完整正文……

====================

第2页｜页面任务

该页完整标题、正文和清单……
```

必须满足：

- 页码数量和图片数量一致。
- 每一页包含图片里实际出现的全部内容文字。
- 按页拼接原文段落后，与母稿内容一致。
- 包含全文最后一句。

错误做法：只写“本页讲市场判断”、起止范围、摘要或字数统计。

## 7. 写入顺序

用户确认母稿并要求执行完整流程后，分页、出图、上传和读回必须连续执行，中间不再请求分页确认或图片确认。只有内容冲突、附件替换、校验失败或工具阻塞时暂停。

1. 读取目标记录，确认附件字段是否为空。
2. 将内容状态切到表中真实存在的处理中选项，例如“生成中”。
3. 使用 `base +record-upsert` 写入封面字段和逐页完整文案。
4. 使用 `base +record-upload-attachment` 按自然顺序逐字段上传图片。
5. 读回文字字段和所有附件字段。
6. 验证通过后将内容状态切到“已定稿”。
7. 再次读回状态和附件。

不同附件字段写入同一记录时默认顺序执行，避免并发覆盖。

## 8. 附件幂等

上传前必须读取图片 01 至最后一个候选字段：

- 全空：正常上传。
- 部分非空：停止，先判断是补缺还是替换。
- 全部非空：除非用户明确要求替换，不再追加。

每个图片字段默认只放一张图。最终包只有 5 张时，图片 06 及以后保持为空。

旧草稿目录和旧附件不能混入最终批次。上传文件必须来自用户最后确认的发布包目录。

## 9. 状态边界

- “生成中”：正在写字段或上传。
- “待确认”：仅用于用户明确要求只生成图片预览、暂不执行完整流程的任务。
- “已定稿”：用户已批准，最终字段和附件已写回并读回一致。
- “是否发布”：只能反映用户真实完成的平台发布；生成或上传飞书附件时不得自动勾选。

飞书字段、分页文案和附件读回一致后，内容生产流程即结束。打开小红书发布页、立即发布或设置定时发布属于独立外部动作，必须得到用户对该次发布的明确授权。

## 10. 最终读回

至少核对：

- 平台内容 ID
- 封面标题和副标题
- 完整分页文案的页数和全文末句
- 图片字段 01 至 N 各一张
- 图片字段 N+1 以后为空
- 文件名与 manifest 顺序一致
- 内容状态为“已定稿”
- “是否发布”未被误改

全部一致后才能向用户报告上传完成。
